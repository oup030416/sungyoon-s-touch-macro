# Lessons from fixes

Paths are relative to `app/src/main/java/com/sungyoon/helper/`. Use `git show <commit>` for evidence; read only relevant entries.

- **Pointer coordinates and visibility.** Migrating coordinates before layout caused initial misalignment. `overlay/pointer/PointerOverlayController.kt` coordinates migration/collection with layout and cancels its delayed fallback on teardown; `PointerOverlayRootView.onSizeChanged` resyncs cached points (`33ff830`). `DraggablePointerView.onDraw` must draw the order label at zero tap radius; visual radius is separate from the touch hitbox (`1211307`, `0a5dc92`). Check first display, resize, and radius zero.

- **Pointer reach and window bounds.** Clamping centers by half the fixed 56dp hitbox excluded 28dp at every edge. Implicit overlay fitting also reduced a 2520x1080 display to a 2441x1017 pointer plane on API 36 with a side cutout. `overlay/OverlayWindowBounds.kt` configures display coverage; `PointerOverlayRootView.moveSelectedPointerToLocalCenter` clamps centers to `0..size-1`. Apply safe system/IME insets only to control surfaces, using the larger bottom inset rather than their sum. Preserve saved screen coordinates and the existing offscreen snap-anchor exception. `updateMoveStickPosition` keeps controls inside that safe area, connects clamped handles diagonally, and avoids the collapsed panel toggle. Check both cutout sides, corners, rotation, keyboard transitions, and immediate recovery from a short viewport.

- **Final drag coordinates.** Saving the last MOVE instead of the newer ACTION_UP position left pointers short of their release target. Both direct-pointer and move-handle listeners in `overlay/pointer/PointerOverlayRootView.kt` apply UP through the existing clamp/snap path before the single end callback. CANCEL must retain the last applied position; taps must only select. Check these event paths separately and verify the saved screen coordinates.

- **Random touch coordinates.** The manager stores absolute display coordinates, but `SungyoonHelperService.resolveTapTarget` previously clipped random samples to the inset `resources.displayMetrics` viewport. A 2520px display with a 2441px application viewport moved a pointer at x=2519 at least 79px inward regardless of a smaller random radius. `service/GestureDisplayBounds.kt` reads fresh default-display bounds; `GestureCoordinatesTest` checks corners, radius zero, nonzero origins, and orientation changes. Preserve the existing disk sampling and edge projection; do not scale saved positions or subtract control insets.

- **Execution after edits.** Ordinary start/resume previously hid the manager while its 250ms option debounce and point writes were unfinished. `overlay/pointer/PointerOverlayController.launchOrdinaryStart` flushes writes/options and guards duplicate or closed-window requests. The service refreshes its six configuration collectors before execution, and `SetServiceController` refreshes items before startup validation. Retire queued old collector emissions before reading fresh snapshots; a completed store edit alone does not ensure a cache collector has consumed it. Restore live collectors even when the waiting start is canceled.

- **Coordinate cache publication.** Separate volatile JSON-key and decoded-list fields in `data/PointsStore.kt` and `PresetStore.kt` could expose the new key with old coordinates to IO readers. Both now use one immutable snapshot in `EncodedValueCache`; `CoordinateStoreCacheTest` exercises the actual stores concurrently. Read the snapshot once per lookup and publish both values with one volatile assignment.

- **Set action and cursor consistency.** Reservation fitting must use the same `HighlightingPoint.isEffectiveDrag` classification as actual dispatch; endpoints within 2px use the tap fallback rather than consuming the drag duration. `SetCursor` also retains the observed ID order to account for preceding rows deleted together with the current row in a conflated flow update. The cursor/runner tests cover deleting A and current C from [A,B,C,D] while paused, ensuring D still executes in the same pass.

- **Set editor acknowledgements.** Feeding every saved configuration back into unfocused fields replaced newer drafts after focus moved, and the next full-form save persisted the old value again. `overlay/set/SetItemPanelViews.kt` keeps a mounted editor's local values authoritative after editing starts; store updates still refresh names and untouched/new editors. Equality with a pending value is not a safe acknowledgement for A-to-B-to-A edits because an older A can arrive first. Check focus transfer, reset, delayed updates, and reopening.

- **Panel sizing.** Panels replacing their own layout parameters broke the parent's `FrameLayout.LayoutParams` contract (`27b3c37`). `overlay/pointer/PointerOverlayRootView.kt` owns placement; preset/reservation panels size their children. Preserve bounded regular body heights and compact bottom padding (`b2a9824`, `5c369ae`). Check both panels in portrait/landscape and short windows, including footer reachability.

- **Preset footer ownership.** Choosing compact mode from the full list height moved the action bar into the list's scroll hierarchy whenever many presets were saved. `PointerOverlayPresetPanelView.updateAdaptiveLayoutMode` now uses the remaining viewport after fixed controls; both layout branches attach the footer directly to the panel. Compact scrolling contains only the header and body. Reserve the measured footer height and actual margins before sizing the scroll region, and do not impose a 120dp body minimum that can push fixed controls below a short viewport.

- **Overlay opening and initial scroll.** Attaching the default root before loading saved panel state exposed an intermediate control screen. `PointerOverlayController.showPreparedWindow` loads state and list data, restores the detached view, and attaches it once; detached panel restoration must skip transition animations. Keep the opening job cancelable and include it in manager ownership so a second toggle cancels preparation and can resume the paused set. `SetListPanelView` aligns the active item in pre-draw after final measurement, with trailing content space for the last item, and removes its observer on detach. Retain the opening anchor through later viewport growth until the first user touch; clearing it at the first successful draw let a taller viewport clamp a 120px target back to 75px. The anchor recomputes trailing space and releases on ACTION_DOWN in `SetListPanelView.dispatchTouchEvent`. Avoid restoring a numeric scroll position after that alignment.

- **Set footer spacing.** Footer children are added after the base `SetPanelView` initialization. Checking `childCount` only in `configureScrollMode` left the actual top margin at zero while `adapt` reserved a positive margin. `overlay/set/SetPanelView.kt` now synchronizes the real margin and padding before measuring the footer; body-end padding lets the last action scroll clear of the fixed footer. Empty footers must also have zero padding to keep their measured height consistent with the reserved space. In `SetPanelView`, attach the footer to the panel in both layout modes and subtract its measured height from the compact scroll viewport; putting it in `compactBody` made actions scroll away on short screens.

- **Blocked execution feedback.** Disabled Android buttons did not invoke the guarded listeners, so tapping a blocked ordinary action could not explain the active set ownership. `PointerOverlayRootView.setOtherExecutionBlocked` and `PointerOverlayReservationPanelView.updateStatusUi` keep these actions visually muted but clickable. Their guarded listeners and `SetServiceController.rejectOrdinaryStart` still reject execution and display the reason. Do not remove the backend guards when changing presentation.

- **Resume cancellation and saves.** Canceling the close/resume coroutine after `flushSharedOptions` canceled the debounce jobs could interrupt the remaining option writes. `PointerOverlayController.hide` now associates navigation with a generation and root identity. Set cancellation invalidates navigation but lets the finite flush finish; stale requests cannot close/resume the manager or clear a newer request's state in `finally`.

- **Korean input.** IME Done submitted preset names during composition. Preserve the composing-span guard and inline, single-line IME configuration in `overlay/pointer/PointerOverlayModalHostView.kt` (`2a67fa8`). Check Korean composition followed by Done.

- **Overlay keyboard focus and viewport.** Requesting the IME immediately after clearing `FLAG_NOT_FOCUSABLE` failed with `PHASE_CLIENT_VIEW_SERVED` on the API 36.1 emulator. `overlay/OverlayImeController.kt` waits for window focus and then posts the request. `PointerOverlayRootView` subtracts IME insets from panel space; `overlay/set/SetPanelView.kt` changes scroll bounds without detaching focused editors and reveals the editor after layout (`9e52ca4`). Check first tap, field transfer, Done, rapid Back, and landscape keyboard visibility; cancel detached screens' pending requests without changing a newer window's flags. See [Android keyboard guidance](https://developer.android.com/develop/ui/views/touch-and-input/keyboard-input/visibility).

- **Reservation resume.** Resuming replayed points from the beginning. Persist the next point offset in `data/ReservationRuntimeStore.kt`; normalize it against the current point count in `SungyoonHelperService.kt`. Clear it on new/stop/reset runs (`d0220c7`). Check pause/resume midway through a sequence and after changing the point count.

- **Update completion and permission flow.** The pending update record survives package replacement. `AppUpdateManager.clearInstalledUpdate` compares its positive target code with the running binary's code before clearing all update keys and artifacts; opening the installer alone must not count as success. Run this before startup UI restoration and pending installation resume. `MainScreenView.refreshUpdateProgress` must reset both download and permission-wait UI when their record disappears. `AppUpdateCompletionTest` covers successful replacement, unfinished newer targets, cleared download IDs, unknown targets, and inaccessible artifacts. Preserve guarded network-state access (`3c157ce`) and the process-level `didInitialUpdateCheck` in `MainActivity.kt` (`027d738`). Check offline launch, permission return, and cancellation without stale progress.

- **Release metadata.** `update/AppUpdateChecker.extractVersionCode` accepts an explicit body field or a trailing code such as `v1.1 (17)` in the release title. When release notes must remain exact, use the title for the code. `AppUpdateManager.checkForUpdates` compares against `BuildConfig.DEV_VERSION_CODE`; replacing an APK with the same code cannot notify existing installations. Increment the internal code for a replacement, then publish the matching title after the APK is available. Keep the tag's source, APK metadata, signer, and checksum consistent. The public version name can remain unchanged.

- **Windows build startup.** A stale `JAVA_HOME` stopped the wrapper; non-ASCII workspace/temp paths caused JNI and loopback socket failures. Use an installed JDK and valid `GRADLE_USER_HOME`, launch from a temporary ASCII `subst` drive, and put `TEMP`/`TMP` on an ASCII path. Kotlin daemon path errors can use the compiler's fallback compilation. Keep overrides process-local and remove the drive afterward; avoid changing project settings to repair one machine.

- **Gesture API compatibility.** The four-argument `StrokeDescription(..., false)` in `service/GestureDispatcher.kt` requires API 26 despite the app supporting API 24; `lintDebug` detects this even when APK assembly succeeds. Use the three-argument constructor for a non-continuing drag ([Android API reference](https://developer.android.com/reference/android/accessibilityservice/GestureDescription.StrokeDescription)).
